# ADR-008：独立网页麦克风网关与会话状态

日期：2026-11-13。状态：已实现，真实 iPhone 验收待完成。

## 决策

手机网页使用独立 HTTP 设置页与 HTTPS/WSS 麦克风入口。复用既有注册、MSA1 及标准混音路径；仅开放页面、公开证书、注册和音频上行。桌面控制面保持 loopback，不为了让手机打开页面而开放整套管理 API。

所有 iOS 线路二维码打开麦克风页面，并显示关联 AirPlay 名称。网页麦克风是独立来源；接收手机其他 App 的媒体音频继续使用用户手动选择的 AirPlay 路径。

来源在线状态取自成功协商的原生 AirPlay 会话，收音状态取自近期音频包，两者分开。RTSP 探测、PCM 管线创建及播放静音均不能替代实际会话状态。停止收音时清空电平和过时延迟。

来源删除使用专用控制消息，不再指望空配置覆盖能删除已发现来源。删除时撤销网页 token、关闭活跃推流、清理来源出线、移除混音来源，并屏蔽该身份的迟到未注册 UDP 包。新的明确注册/发现可以重新添加该来源。

## 替代方案

- 把桌面控制 API 全部绑定 LAN：拒绝，扩大了暴露面，且 HTTP 仍不能让 iOS 麦克风合法采集。
- 仅给二维码更名：拒绝，打包缺少网页资源且原来端口不可达，必须修复实际入口。
- 仅凭音频包超时判定离线：拒绝，播放暂停时手机仍可能保持连接。
- 网页替代原生后台音频节点：拒绝，网页采集必须明确前台限制。

## 风险

iPhone 信任本地 CA 是必须由用户完成的设置；自签证书不是自动授权。证书含访问 IP，地址改变需续签服务器证书。私钥仅留本机并限制目录 ACL。HTTPS 入站规则需管理员在 Private/LocalSubnet 范围配置。

UxPlay 变更保留对应源码/补丁；模拟会话与本地回读只能验证本机链路，不能证明真实 iPhone 握手、视频不卡顿或完整端到端延迟。
