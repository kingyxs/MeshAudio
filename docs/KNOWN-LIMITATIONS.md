# 已知限制与待验收项目

更新：2026-11-14。

- Windows x64 是当前交付目标，不支持 macOS。
- Android 原生节点已恢复为独立可构建模块；麦克风与媒体分别发送 48 kHz PCM。Android 当前未实现 Opus/省带宽编码，不能把 WebSocket 兼容模式称为省带宽模式。iOS 原生 App/ReplayKit 扩展仍未交付。
- 公开签名的 `MeshAudio-Android-0.3.1-release.apk` 由同一源码重新构建并签名，未在真机重跑 USB/Wi-Fi 两组 15 项验收；真机证据绑定 debug 包。两种签名不能直接覆盖安装，升级需先卸载旧 debug 版（会清除应用数据并重新授权）。
- Android 媒体每次新会话都需用户确认；应用或系统可禁止/撤销播放捕获。不同 Android 版本、厂商后台策略和锁屏政策需要分别真机验收，不能把某一手机的结果推广到所有设备。
- AirPlay 需要 iPhone 手动选择接收器；Web 页面无法自动打开并选择屏幕镜像设备。DRM 和通话音频不保证可捕获。
- 网页麦克风不能替代 iOS 原生后台音频采集，锁屏/后台可能暂停，远程麦克风权限需要可信 HTTPS。
- 虚拟麦克风采用外部 VB-CABLE。未交付 MeshAudio 自有签名内核驱动。VB-CABLE 和 Bonjour 的系统安装可能需要管理员授权与重启。
- 新连线无需中断其他路由，但通道增益为零、静音或无输出路径时仍然无声。
- 显示的单来源延迟是 MeshAudio 已知处理段测量，不是手机采集到电脑扬声器的完整端到端延迟。AirPlay 本身可能存在明显缓冲延迟。
- 前一轮长测在统计刷新窗口外发现两处波形跳变，连续性报告仍为失败；本次交互和安装改动不能替代这一问题的修复与听感验证。
- 尚需真实 iPhone/实际耳机、两台 iPhone 并发、网络抖动和至少 30 分钟连续运行验收。合成音频、浏览器模拟输入和构建成功不代表上述项目通过。
- 发布前需要在干净 Windows 验证第三方安装器、UAC 取消、驱动重启、WebView2 下载和卸载。开发机不会重复安装现有驱动来假装完成这一门禁。
- 未配置商业代码签名证书；Windows SmartScreen 可能提示未知发布者。
