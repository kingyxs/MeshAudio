# CLA 签署记录

本目录存放 [MeshAudio 贡献者许可协议（CLA）](../CLA.md) 的签署记录。CLA 用于确认贡献者有权提交代码，并授权本项目按 `GPL-3.0-or-later` 分发其贡献；它不是版权转让，也不改变项目的开源许可证。

## 谁需要签署

- 向仓库提交 Pull Request、补丁或其他会被纳入仓库的内容的个人贡献者。
- 代表公司/组织提交，或贡献属于职务创作、受委托创作的，由该实体的授权代表按 CLA §7 签署实体记录。
- **不需要**签署：提交 Issue、复现步骤、测试反馈、文档建议等不纳入仓库内容的参与方式。

## 签署步骤

1. 阅读 [CLA.md](../CLA.md)、[CONTRIBUTING.md](../CONTRIBUTING.md) 与 [docs/LICENSING.md](../docs/LICENSING.md)。
2. 复制 [SIGNATURE-TEMPLATE.md](SIGNATURE-TEMPLATE.md)，在 `signatures/` 下新建 `<你的 GitHub 用户名>.md`，按模板填写；实体贡献者额外填写实体全称、授权代表与职务。
3. 在 PR 描述中注明签署记录文件名，并勾选 PR 模板里的 CLA 勾选项。
4. 维护者核验后合并。首次签署对之后的所有贡献持续有效，无需每次 PR 重签。

## 记录内容与隐私

签署记录只包含：CLA 版本、签署类型、姓名或实体全称、GitHub 用户名、联系邮箱（**可使用 GitHub 提供的 noreply 邮箱**）、实体授权代表（如适用）、签署日期与协议声明。

请勿在签署记录或 PR 中提交：私钥/凭证、真实用户音频、本机局域网 IP、真实设备标识、未经脱敏的日志、个人身份证件或完整 AppData 目录。维护者只按 GitHub 用户名核验 PR 作者身份，不收集额外个人信息。

## 维护者核验

当前**没有配置自动 CLA 机器人**，采用人工核验：

1. 签署文件名与 PR 作者的 GitHub 用户名一致；
2. CLA 版本、签署日期与声明文本完整，未被改写授权范围；
3. 实体贡献者填写了授权代表，并确认其有权代表该实体；
4. PR 中的代码不含未标注来源的第三方材料或专有组件。

核验通过后合并 PR。若日后接入 CLA 机器人，会在本文件、`CLA.md` 与 `CONTRIBUTING.md` 同步公告，并保留现有签署记录。

## 撤回

贡献者可按 CLA §8 书面通知维护者撤回，撤回不溯及撤回前已接受、已分发的内容，也不影响 GPL 已授予下游的许可。当前请通过仓库主页公布的维护者联系渠道或私有安全问题报告渠道提出；**不要**在公开 Issue 中贴个人身份信息。
